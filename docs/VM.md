# Архитектура виртуальной машины TuxPL 2.0.0 (Unified VM)

## 1. Введение

В версии 2.0.0 виртуальная машина TuxPL совершает качественный переход от традиционного разделения гарвардского типа к **фон-неймановской архитектуре с единой изолированной памятью (Unified Memory)**.

## 2. Модель памяти и структура `TuxCell`

Вся память VM состоит из строго 65536 ячеек (`TUX_MEM_SIZE = 65536`, адресация от `0` до `65535`):

```c
typedef struct {
    int64_t  val;          /* Каноническое значение данных ячейки */
    uint16_t raw_code;     /* Закодированный 16-битный образ инструкции */
    uint8_t  type_tag;     /* Тип: TUX_TYPE_I8..I64, TRIT, ADDR, OPCODE */
    uint8_t  age;          /* Возраст: TUX_AGE_YOUNG, ADULT, OLD, DEAD */
    uint8_t  gen;          /* Поколение клонирования: 0..255 */
    uint8_t  flags;        /* Битовые флаги: EXECUTABLE, MUTATED, DORMANT... */
    uint32_t lineage;      /* Детерминированный идентификатор родословной ячейки */
    uint32_t exec_count;   /* Эволюционный счётчик исполнений ячейки */
} TuxCell;
```

### Семантика полей ячейки:
- **`val`** — каноническое числовое значение ячейки (используется стеком, переменными, арифметикой).
- **`raw_code`** — закодированное представление инструкции. При загрузке в память исходный опкод размещается в `raw_code`.
- Если `type_tag == TUX_TYPE_OPCODE`, то первичным входом для декодера является `raw_code`.
- Для всех остальных `type_tag` первичным входом для декодера выступает `val`.
- В ячейке **не хранится постоянный декодированный опкод**: рантайм-декодер синтезирует команду динамически.

## 3. Динамический рантайм-декодер (`decoder.c`)

Декодер является **чистой детерминированной функцией**:

```c
DecodedInstruction decode_instruction(
    const TuxCell *cell,
    uint16_t pc,
    uint64_t program_key,
    const int64_t regs[4],
    const TuxGenome *genome,
    uint64_t entropy_pool,
    uint8_t prev_width,
    int is_apocalypse
);
```

### Инварианты декодирования:
1. **Мёртвая ячейка (`age == TUX_AGE_DEAD`)**: строго и безусловно декодируется в `OP_NOP` с шириной `1`.
2. **Спящая ячейка (`flags & TUX_FLAG_DORMANT`)**: безопасный `OP_NOP`.
3. **Возрастные домены**:
   - `YOUNG`: `raw_op = (c_in + shift) % 42`
   - `ADULT`: `raw_op = (c_in + shift + G[1]) % 42`
   - `OLD`: `raw_op = tux_crazy64(c_in + shift, cell.age ^ G[2]) % 42`
   - `DEAD`: гарантированный `OP_NOP`
4. **Динамическая ширина инструкции $W_t \in [1, 4]$**:
   $$W_t = ((\text{tux\_crazy64}(\text{cell.val}, G[1] \oplus W_{t-1}) \gg 16) \& 0x03) + 1$$
   Маскирует размер аргумента (1 байт, 2 байта, 4 байта или 8 байт).

## 4. Модель двух программных счётчиков (Dual PC)

Каждый контекст (`TUX_A`, `TUX_B`) обладает двумя программными счётчиками:
- **`PC_CODE`**: указывает на адрес текущей исполняемой инструкции.
- **`PC_DATA`**: указывает на адрес чтения/записи для косвенных операций с памятью.

Инструкции управления счётчиками:
- `PUSH_PC`: кладёт текущий `PC_CODE` на вершину стека с типом `TUX_TYPE_ADDR`.
- `SET_PC`: снимает адрес со стека и устанавливает `PC_CODE`.
- `SWAP_PC`: атомарно меняет местами `PC_CODE` и `PC_DATA`.
- `ADD_PC`: добавляет относительное смещение со стека к `PC_CODE`.
- `XOR_PC`: выполняет побитовое XOR `PC_CODE` с маской со стека.

## 5. Расширенная таблица опкодов TuxPL 2.0 (42 опкода)

| Опкод | Имя | Назначение |
|---|---|---|
| 0 | `OP_NOP` | Холостая операция |
| 1..4 | `OP_ADD`, `OP_SUB`, `OP_MUL`, `OP_DIV` | Арифметика стека |
| 5..7 | `OP_DUP`, `OP_SWAP`, `OP_POP` | Манипуляции со стеком |
| 8 | `OP_PUSH` | Загрузка константы |
| 9..10 | `OP_LOAD`, `OP_STORE` | Переменные с проверкой владения (Borrow Checker) |
| 11..12 | `OP_LOADIND`, `OP_STOREIND` | Прямой доступ к Unified Memory |
| 13..15 | `OP_JMP`, `OP_JZ`, `OP_JNZ` | Условные и безусловные переходы |
| 16..20 | `OP_LIST*` | Динамические списки |
| 21..22 | `OP_PRINT*` | Вывод символов и чисел |
| 23 | `OP_INPUTNUM` | Ввод числа |
| 24..25 | `OP_REGGET`, `OP_REGSET` | Регистры `Tu RAX`..`RDX` |
| 26 | `OP_FISH` | Пополнение запаса рыбы (предотвращение голода) |
| 27 | `OP_CRAZY` | Троичная операция Malbolge над 64 битами |
| 28 | `OP_CAST` | Явное приведение типов |
| 29 | `OP_DIR` | Изменение направления движения PC (2D-режим) |
| 30 | `OP_PUSH_PC` | Чтение текущего PC_CODE на стек |
| 31 | `OP_SET_PC` | Установка PC_CODE из вершины стека |
| 32 | `OP_SWAP_PC` | Обмен PC_CODE <-> PC_DATA |
| 33 | `OP_ADD_PC` | Относительный прыжок PC_CODE += off |
| 34 | `OP_XOR_PC` | Побитовая маскировка PC_CODE ^= mask |
| 35 | `OP_CLONE` | Клонирование ячейки с эволюцией поколения |
| 36 | `OP_DECAY` | Принудительный распад ячейки в DEAD/NOP |
| 37 | `OP_WAKE` | Пробуждение ячейки из состояния DORMANT |
| 38 | `OP_REINTERPRET` | Смена типа данных вершины стека без конверсии бит |
| 39 | `OP_UNDO` | Термодинамический откат обратимого состояния данных |
| 40 | `OP_PAY_TIME` | Выплата накопившегося долга времени ценой рыбы |
| 41 | `OP_CMP` | Троичное сравнение (-1, 0, 1) |
