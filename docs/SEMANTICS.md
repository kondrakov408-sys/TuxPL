# Семантический цикл и инварианты TuxPL 2.0.0

## 1. Канонический 9-фазный цикл выполнения

Виртуальная машина выполняет инструкции в строгом математическом порядке:

```
[FETCH] -> [DECODE] -> [EXECUTE] -> [MUTATE] -> [REGISTER COUPLING] -> [GENOME UPDATE] -> [DORMANT RESONANCE] -> [PC UPDATE] -> [SCHEDULE] -> step++
```

1. **ФАЗА 1: FETCH**
   Считывание ячейки `memory[active_ctx.pc_code]`.
2. **ФАЗА 2: DECODE**
   Чистая функция `decode_instruction` синтезирует опкод, маскирует операнд динамической шириной $W_t$ и определяет ширину следующей инструкции $W_{t+1}$.
3. **ФАЗА 3: EXECUTE**
   Выполнение команды над текущим контекстом (`active_ctx`), начисление долга времени, потребление рыбы, валидация типов и стека.
4. **ФАЗА 4: MUTATE**
   Вызов `tux_mutate_cell`: инкремент `exec_count`, старение ячейки при пороге 3 исполнений, мутация `val` и пересчёт `raw_code`.
5. **ФАЗА 5: REGISTER COUPLING**
   Внутрирегистровое дифференциальное связывание регистров `act->regs` на основе матрицы $C$:
   $$R_0 \oplus= \Delta_0, \quad R_1 += \Delta_1, \quad R_2 \oplus= \Delta_2, \quad R_3 += \Delta_3$$
6. **ФАЗА 6: GENOME UPDATE**
   Эволюция хромосом $G_0 \dots G_3$ на основе результата операции, энтропии и состояния регистров.
   Шаг энтропии `tux_entropy_step`.
7. **ФАЗА 6.1: DORMANT RESONANCE**
   Фоновое сканирование памяти на совпадение резонанса $(\text{Genome}[3] \oplus \text{addr}) \pmod{256} == 0$.
8. **ФАЗА 7: PC UPDATE**
   Обновление `PC_CODE` **только для активного контекста**, завершившего текущий шаг:
   - При переходе: `pc_code = target % 65536`.
   - При последовательном шаге: `pc_code = (pc_code + dir_offset) % 65536`.
9. **ФАЗА 8: SCHEDULE**
   Планировщик оценивает состояние памяти и выбирает активный контекст на следующий шаг (`TUX_A` или `TUX_B`).
10. **ФАЗА 9: step_counter++**
    Инкремент глобального счётчика шагов.

## 2. Ключевые инварианты TuxPL 2.0.0

- **Детерминизм**: При одинаковых оверрайдах окружения любые две трассы исполнения на 100% совпадают байт-в-байт.
- **Однозначность входа декодера**: Для ячеек `TUX_TYPE_OPCODE` первичным входом является `raw_code`; для остальных — `val`.
- **Изоляция UNDO**: Откат обратимого состояния никогда не восстанавливает мутации кода, возраст ячеек, историю поколений клонов и эволюцию генома.
- **Предел клонирования**: Поколение 255 является абсолютным биологическим пределом стаи.
